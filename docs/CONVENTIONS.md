# MittenLink — Engineering Conventions

This document is the contract every contributor (human or AI) follows. Read it before writing code.

## Stack

- **Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4 + shadcn/ui (Base UI primitives)**.
  Next 16 differs from older versions: `params`/`searchParams`/`cookies()`/`headers()` are **async**; `middleware.ts` is now `proxy.ts`.
  Docs for this exact version live in `node_modules/next/dist/docs/`.
- **PostgreSQL** with PostGIS, pg_trgm and unaccent. Locally this is **PGlite** (Postgres compiled to WASM, file-backed in `.data/pglite`); in production it is **Supabase** Postgres. The *same* SQL migrations in `supabase/migrations/` run in both.
- Dev server: `npm run dev` (uses **webpack** — Turbopack's dev cache hits Windows file locks on some machines).
- Typecheck: `npm run typecheck`. Route types (`PageProps<'/route'>`, `LayoutProps`) are generated by `npx next typegen` / `next dev`.

## Directory layout

```
supabase/migrations/        SQL migrations (schema, functions, RLS) — source of truth
db/local/                   Supabase-compat shim applied only to PGlite
scripts/db.ts               db:reset / db:migrate / db:seed
src/lib/db/                 Driver abstraction (pglite | postgres), migrations runner, seed data
src/lib/auth/               Session + auth adapter (local | supabase), guards, current user
src/lib/domain/             Cross-cutting business workflows (claims, verification, change requests)
src/lib/server/             audit(), notify(), rate limiting, action helpers, analytics
src/lib/integrations/       Swappable adapters (email, billing, maps, AI discovery, storage)
src/lib/data/               Read-model query helpers used by pages
src/lib/format.ts, labels.ts, links.ts   Shared display helpers (client-safe)
src/components/ui/          shadcn/ui primitives (Base UI)
src/components/common/      Badges, page headers, empty/error states, pagination, DataTable
src/components/forms/       Accessible form fields + FormMessages + SubmitButton
src/components/layout/      Header, footer, demo banner, workspace shell
src/app/                    Routes
```

## Data access rules (security-critical)

- Import DB helpers from `@/lib/db` **only in server code**.
- **Reads for public pages**: `asPublic(sql => …)` — runs as Postgres role `anon`, RLS enforced.
- **Reads/writes on behalf of the signed-in user**: `asCurrentUser(sql => …)` from `@/lib/auth` — role `authenticated`, `auth.uid()` = user id, RLS enforced. Use this for saving resources, submitting reports, reading one's own notifications, etc.
- **Privileged workflows** (claim review, verification, publishing, billing, admin CRUD, staff reads of internal tables): first check authorization (`assertRole('admin', 'super_admin')`, `assertOrganizationAccess(orgId)`, `requireAdmin()` …), then use `asService(sql => …, actorId)`. `asService` bypasses RLS — **never call it without an explicit role check first**.
- All SQL uses `$1, $2` parameters. Never interpolate user input into SQL. (Column names in dynamic SQL must come from code-level whitelists.)
- Cast aggregates: `count(*)::int`, numeric → `::float8`. Timestamps come back as `Date` objects.
- Geography: read coordinates with `extensions.st_y(geog::extensions.geometry) as lat, extensions.st_x(geog::extensions.geometry) as lng`.
- Every mutation that matters writes an **audit entry in the same transaction** (`audit(sql, {...})` from `@/lib/server/audit`).
- In-app notifications: `notify(sql, {...})` inside the transaction; it returns a deferred email sender. After the transaction commits, call `deliverAfterCommit([...senders])` and surface the returned warning (if any) in the success message. Email failure must never lose saved data.
- Internal notes live in `internal_notes` and verification `internal_notes` columns — never render them on public pages. Public verification info comes from the `public_verification_history` view; public family reports from `public_family_experiences`.
- Providers **never** write directory tables. Provider edits go through `submitChangeRequest()` (`src/lib/domain/change-requests.ts`), which creates a moderated change request + verification task. Verifiers resolve tasks with `resolveVerificationTask()` (`src/lib/domain/verification.ts`), which applies approved changes. Claims use `saveClaim()` / `reviewClaim()` (`src/lib/domain/claims.ts`).
- Payment/billing state is written only by server-side billing code. Verification status must never depend on listing tier.

## Schema quick reference

`listings` is the supertype for every public record (`kind` = organization | service | program | resource | event) holding slug, title, summary, description, `publication_status` (draft/pending/published/archived), `verification_status` (unverified/pending_review/verified/needs_update/unable_to_verify/archived), `last_verified_at`, `next_review_at`, `virtual_available`, `primary_city`, `primary_county_id`, `is_demo`. Typed tables share the id: `organizations`, `services` (organization_id, age_min/max, eligibility, is_free, referral_required, waitlist_status, in_person, home_based, contact_*), `programs`, `resources` (resource_type, body, source_*), `events` (starts_at, ends_at, venue, geog, is_in_person, registration_url, accommodations). Also `organization_locations` (geog, hours jsonb, wheelchair_accessible, accessible_parking, transit_info, appointment_required, virtual_services, status, is_primary), `organization_contacts` (provenance), `organization_media`, `service_locations`, `service_payment_options`.

Relationships (all FK-enforced): `listing_categories`, `listing_populations`, `listing_disability_categories`, `listing_languages`, `service_areas` (statewide | county | radius), derived `listing_points` (physical points used by radius search/map).

Workflow tables: `provider_claims`, `provider_members`, `provider_change_requests`, `community_corrections`, `verification_tasks`, `verification_history`, `verification_sources`, `family_experience_reports`, `community_submissions`, `source_watch_sources`, `source_watch_candidates`, `source_watch_tasks`, `duplicate_suggestions`, `listing_merges`, `outreach_contacts`, `outreach_interactions`, `internal_notes`, `saved_resources`, `saved_searches`, `search_logs`, `failed_searches`, `resource_gap_flags`, `analytics_events`, `subscriptions`, `billing_events`, `notifications`, `audit_logs`, `platform_settings`, `profiles`, `roles`, `user_roles`, `counties`, `places`, `categories`, `populations`, `disability_categories`, `languages`, `payment_options`, `search_synonyms`.

Search: `public.search_listings(p_query, p_kinds, p_categories, p_populations, p_delivery, p_verified_only, p_accepting_only, p_free_only, p_insurance_only, p_accessible_only, p_language, p_org_type, p_lat, p_lng, p_radius_miles, p_county_id, p_include_statewide, p_sort, p_limit, p_offset)` → `(id, kind, distance_miles, rank, match_scope, total_count, local_count, statewide_count)`. `match_scope` ∈ nearby | serves_area | statewide | anywhere. Call with named args (`p_query => $1`).

Schema changes: add a **new** migration file (never edit applied ones) named `supabase/migrations/20260902XXXXXX_short_name.sql`, grant privileges + enable RLS + add policies for new tables, then apply to the running dev database with `curl -X POST http://localhost:3100/api/dev/migrate`.

## Auth & roles

- `getCurrentUser()` → `{ id, email, fullName, roles[], organizations[] } | null` (cached per request).
- Page guards: `requireUser(next)`, `requireRole([...])`, `requireStaff()`, `requireAdmin()`, `requireOrganizationAccess(orgId)`.
- Action guards: `assertSignedIn()`, `assertRole(...roles)`, `assertOrganizationAccess(orgId)` (throw `AuthorizationError`, converted to friendly messages by `runAction`).
- Roles: `community_member`, `provider`, `verifier`, `admin`, `super_admin`. Only super admins manage roles.
- Provider pages use `getActiveOrganization(user)` (`src/lib/provider/active-org.ts`).
- Dev only: `GET /api/dev/login-as?email=admin@mittenlink.demo&next=/admin` sets a session cookie (for curl/Playwright). Demo accounts: `admin@`, `verifier@`, `provider@`, `community@mittenlink.demo`, plus `david.reynolds@example-demo.org`, `rachel.nguyen@example-demo.org`, `hannah.olsen@example-demo.org`, etc.

## Server actions & forms

- Put actions in an `actions.ts` file with `"use server"` next to the route (or `src/lib/actions/*.ts` if shared). Files with `"use server"` may export only async functions.
- Signature for form actions: `(prev: ActionState, formData: FormData) => Promise<ActionState>`, wrapped in `runAction(formData, async () => {...})`. Validate with zod via `parseForm(schema, formData)`. Throw `UserFacingError(message, fieldErrors?)` for expected problems.
- Client forms: `const [state, action] = useActionState(myAction, idle)` (import `idle` and the `ActionState` type from `@/lib/server/action-types`, never from `action.ts`). Render `<FormMessages state={state} fieldLabels={...} />` at the top, then `TextField`, `TextAreaField`, `SelectField`, `CheckboxField`, `RadioGroupField` from `@/components/forms/fields`, and `<SubmitButton>`. Mark required fields with `required` (adds visible and programmatic indicators); show `<RequiredNote />` once per form.
- After mutations call `revalidatePath()` for affected pages. Use `redirect()` for flows that move to another page.
- Simple button actions (e.g. "Mark read") can be `<form action={serverFn}>` with hidden inputs.

## UI & accessibility checklist (WCAG 2.2 AA)

- One `<h1>` per page (use `PageHeader`), logical heading order, landmarks via layout.
- All interactive targets ≥ 44px tall where practical (buttons/inputs already are). Use `buttonVariants()` on `<Link>` for link-buttons.
- Never communicate status by color alone — `VerificationBadge`, `StatusPill`, `ListingTierBadge` include text + icon.
- Link text must make sense out of context ("View details for {name}", or add `<span className="sr-only">`).
- Tables: `DataTable` (real table with caption + scoped headers on desktop, cards on mobile). No horizontal-scroll tables on phones.
- Pagination: `Pagination` component (real links, `aria-current`).
- Dynamic updates: announce with a polite live region (`role="status"`). Errors: `role="alert"` + move focus (FormMessages does this).
- Every async screen: loading (`loading.tsx` or skeleton), empty (`EmptyState`), error (`ErrorState` / `error.tsx` with retry), success message.
- No raw errors to users. Catch and show friendly text; log details server-side.
- Colors: use theme tokens (`text-muted-foreground`, `bg-success-soft`, `text-success`, `bg-warning-soft`, `text-warning`, `bg-danger-soft`, `text-danger`, `bg-info-soft`, `bg-enhanced-soft`, `text-enhanced`, `bg-secondary`, `text-primary`). Don't use low-contrast greys like `text-gray-400`.
- Respect reduced motion (global CSS handles transitions). Avoid decorative animation.
- Mobile first: check layouts at 320px width.
- Dates: `formatDate`, `formatMonthYear`, `formatDay` (date-only columns), `formatDateTime`, `formatRelative` from `@/lib/format`. Labels for enum values: `@/lib/labels`. URLs for records: `listingHref(kind, slug)` from `@/lib/links`.

## Copy & content

- Plain language, person-respecting, no stereotypes. English only.
- Verification wording: "reviewed by MittenLink on {date}" — never imply medical/professional endorsement.
- Enhanced listings are labeled "Enhanced Listing" and never ranked as if objectively better.
- AI output is labeled **"AI Suggested — Requires Human Review"** only when a real model produced it; the rules-based fallback is labeled **"Automated Suggestion (rules-based) — Requires Human Review"**.
- Demo data is fictional; the global banner says so. Don't add real organizations, people, or contact details.

## Working in parallel (for AI agents)

- A single shared dev server runs at **http://localhost:3100** and owns the PGlite database. **Do not** start another dev server, run `npm run build`, run `npm run db:*`, delete `.next` or `.data`, or kill node processes.
- Verify pages with `curl -s http://localhost:3100/<path>` (first request to a route compiles, allow ~60 s). For signed-in pages: `curl -s -c /tmp/<you>.txt "http://localhost:3100/api/dev/login-as?email=admin@mittenlink.demo&next=/admin" -o /dev/null` then `curl -s -b /tmp/<you>.txt http://localhost:3100/admin/...`. Strip React text separators with `sed 's/<!-- -->//g'` when grepping.
- Only edit files in your assigned area. If you need a change to a shared file (`src/lib/**`, `src/components/common/**`, `src/components/forms/**`, layouts), make a minimal additive change and mention it in your final report.
- Run `npx tsc --noEmit` before finishing; fix errors in your files (ignore errors clearly belonging to another agent's in-progress files, but report them).
